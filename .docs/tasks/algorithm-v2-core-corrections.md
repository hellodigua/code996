# 核心算法 V2 第一阶段修正

## 背景

当前 996 指数能够反映提交集中在晚间、周末的总体方向，但核心计算、工作时间展示、趋势和成员分析之间存在时间粒度与语义不一致。2026-07-31 使用真实业务目录 `/Users/digua/coding/hifive/agm-music` 做了只读回归，统一分析 2025 年、作者时区 `+0800`、非合并提交。

达到最低 50 条提交要求的 4 个仓库共包含 2557 条提交；另有 1 个仓库仅 28 条提交，按现有样本门槛不评分。

| 阶段                                   | 被判为加班的提交数 | 相对前一步 |
| -------------------------------------- | -----------------: | ---------: |
| 当前算法                               |                318 |          - |
| 日期与时间联合判定，但保留当前整点截断 |                320 |         +2 |
| 保留 committer date，修复半小时边界    |                406 |        +86 |
| 改用 author date，并保留分钟边界       |                413 |         +7 |

真实工作样本表明，第一阶段最主要的确定性误差是半小时被 `parseInt` 截成整点。日期与时间联合判定、author/committer 时间源切换仍有价值，但不属于本阶段主改造范围。

## 第一阶段目标

1. 计算层保留半小时边界，统一将 `HH`、`HH:00`、`HH:30` 转为 `minuteOfDay` 后比较。
2. 区分两个时间概念：
   - `standard work window`：正常工时边界，用于判定加班；自动模式为推测开始时间后的 9 小时，手动模式使用 `--hours`。
   - `observed activity end`：仓库实际提交活动延伸到的时间，仅作为诊断证据，不能反向扩大正常工时。
3. 自动工时置信度低于 60% 时，不把单一推测值包装成确定结论；报告附带常见工时场景的指数范围。
4. `--hours` 必须贯穿总览、月度趋势、单仓库团队分析和多仓库团队分析。
5. 为核心算法新增直接单元测试和受控 Git fixture，避免只依赖输出层测试。

## 用户可见行为

### 可靠或手动工时

- 核心指数继续显示单值。
- 工作时间同时展示标准工时窗口和观察到的活动结束时间。
- 手动 `--hours` 的置信度保持 100%，不生成推测场景。

### 低置信度自动工时

- 保留自动推测结果作为默认计算值，避免破坏现有排序和 Schema。
- 同时计算去重后的常见场景：`9-18`、`9.5-18.5`、`10-19` 和自动推测窗口。
- ReportData 提供最小/最大指数与各场景结果；终端、Markdown 和 Web 明确标记“低置信度，仅供参考”。

## 兼容边界

- 本阶段不重新标定 `996 指数 = 加班比例 × 3`。
- 本阶段不切换 author date / committer date 默认值。
- 本阶段不移除周末概率修正公式。
- 本阶段不重做项目类型分类器。
- JSON Schema 只增加可选字段，现有字段保留。
- `--hours` 的修复会使趋势和成员结果发生预期变化，这是此前参数未贯穿造成的错误，不做旧行为兼容。

## 受控验收样本

1. `9:30` 在 `9.5-18.5` 中属于正常时间，`18:30` 属于加班时间。
2. 标准 `9-21、周一至周六` 样本：
   - 核心指数保持约 100 以上的高风险方向；
   - 工作日 18:00 后提交不能因观察到 21:00 活动结束而被归零。
3. 低置信度自动识别生成工时场景和指数范围，手动工时不生成。
4. 同一 `--hours` 在总览和每个月份得到相同的正常工时定义。
5. 成员分析使用成员自己的每日首提样本；显式历史时间范围不被“当前日期往前 6 个月”错误清空。

## 实施结果

第一阶段已在 `feat/algorithm-v2-core-corrections` 落地，并完成端到端 CLI 回归。当前本地仓库在 2025 年、`+0800`、非合并提交、中国节假日自动模式下的结果如下：

| 仓库                | 当前提交数 | 自动标准工时 | 自动指数/区间          | 手动 `9.5-18.5` 指数 |
| ------------------- | ---------: | ------------ | ---------------------- | -------------------: |
| agm-admin-web       |        202 | `10-19`      | 15 / 15–39             |                   18 |
| agm-h5-nuxt2        |        147 | `9.5-18.5`   | 36 / 21–54             |                   36 |
| agm-web             |       2151 | `9.5-18.5`   | 51（置信度 69%，可靠） |                   51 |
| hifive-agm-electron |         58 | `10-19`      | 0 / 0–27               |                   21 |

端到端结果包含中国节假日修正，并基于回归执行时的当前仓库状态，因此不与前述隔离算法候选值逐项等同。更重要的验收结果是：半小时边界已真实进入采集和判定，三个低样本仓库不再只给一个确定分数，可靠样本仓库保持单值。

真实仓库只用于本地验证，临时 JSON 位于系统临时目录；作者、邮箱和提交明细未写入仓库。
